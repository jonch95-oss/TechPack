## 1. Real proto packs are lean and reference-driven → make "reference answers" first-class

None of the seven packs states:
- edge treatment, construction rows or thread;
- tolerances or a BOM;
- hardware placements in mm;
- zip length / ends / slider;
- logo offset;
- due date;
- interior pocket sizes (most packs).

They answer with references instead.

**Phrases seen across the packs** (wording paraphrased, meaning exact):
- *Please follow sample / reference images for handle construction.*
- *Please use reference images for shape and construction.*
- *Same as <style #>.*
- *Same construction as <style #>.*
- *From previous development.*
- *Use the same material from this bag.*
- *Reference this charm, follow the increased size.*
- *Scale as needed to match size on CAD.*
- *We are open to all affordable options.*
- *Artwork to be provided.*
- *Quality reference* — a swatch card shown for quality, with no chip chosen.

**Build:**
1. **Reference answer type.** Every question accepts a *reference answer* as well as a value. Kinds:
   - `PER_IMAGE(ref photo id)`
   - `SAME_AS(style # [, part])` — links to that pack when it exists in the studio
   - `PREVIOUS_DEVELOPMENT(text / photo)`
   - `FACTORY_STANDARD`
   - `SCALE_TO_CAD`
   - `OPEN_OPTIONS(text)`
   - `TO_BE_PROVIDED`

   A reference answer is a **settled** answer at PROTO and prints as written ("PLEASE FOLLOW REFERENCE IMAGE 2", "SAME AS LAB-HB-#####").
2. **At PRODUCTION:**
   - `TO_BE_PROVIDED` and `OPEN_OPTIONS` block.
   - `SAME_AS` must resolve to a pack or library item in the studio (and is shown inline).
   - The rest are allowed.
3. **Recalibrate the PROTO gate to these packs.** At PROTO, require only:
   - style code, item, brand, date;
   - a render or flat per colourway;
   - overall dimensions (at least the ones the category needs — PLAY gives drop + W + H only);
   - per colourway: colour and material (library swatch, Icon fabric code, supplier card, *or* a reference answer);
   - logo method + location for each logo;
   - hardware identity for each visible part (library code, *or* a description, *or* a reference answer);
   - the instruction notes.

   Jon's earlier requirement — hardware specs, full strap/handle specs and interior — still applies, but **a reference answer satisfies it**. Everything else may be blank at PROTO; a blank prints as nothing, never as a guess.
4. **Acceptance:** each of the seven packs, entered exactly as the original states it, passes the PROTO gate with zero blockers. The resulting PDF carries the same facts.

## 2. Layouts: one engine, several page templates, chosen per brand

Icon's packs use four page styles. Implement them as **templates in one engine**, selected per brand in the Rulebook and overridable per pack. The brand logo still swaps automatically (Jon's original decision).

### T1 Style-box layout (most common — Champion, Palm Angels, Ted Baker)
- **Page:** landscape. Size is set per template: the packs use 13.68 × 8.5 in, 13.13 × 8.5 in and letter.
- **Top-left box:** `STYLE CODE:` value, the **date in red** at its right, and `ITEM:` value in bold. L/AB's variant uses `STYLE NAME / DATE / BRAND` rows.
- **Top-right box:** `BRAND:` above the brand logo.
- **Page tag:** "P1", "P2"… bottom-right. No "PAGE n/N", no revisions block.
- **Headline instruction in large type** where needed ("PLEASE SAMPLE IN <SIZE>", "PLEASE SAMPLE IN THESE TWO COLORS").
- **PRODUCT FEATURES box:** bulleted with "-", top-right of page 1.
- **Overall dimensions** as one line under the features box ("W" x H" x D"") *and* as red dimension lines on the flat.
- **Reference images** in a thin red frame, with a red caption such as "PLEASE USE REFERENCE IMAGES FOR SHAPE AND CONSTRUCTION".
- **Typical page order:**
  1. overview + features + dimensions;
  2. reference images;
  3. colour key + variant table;
  4. trims at actual size + fabric references;
  5. lining;
  6. logo artwork;
  7. merchandising / hangtag;
  8. master carton label.

### T2 Icon masthead layout (PINK013 — Pink London)
The current template, unchanged.

### T3 Component sheet (Palm Angels luggage parts)
- One page per component, portrait letter.
- Brand wordmark top-left; title `CODE_NAME` (e.g. `PA_LUG_00X_<PART NAME>`).
- The drawing at **1:1** with dimensions drawn *on* the views.
- The finish written as a headline ("MULTI-COLOR METAL FINISH") above the physical **finish-standard photo**.
- An "AI RENDERING" panel and an optional sample photo.
- No title block.

See §7.

### T4 Portrait board (PLAY)
- One tall portrait page.
- Brand logo top-left; one column per style number, each with the render and a spec block under it (`STYLE# / COLOR / FABRIC / LINING / LABEL / ZIPPER …`).
- Embellishment and logo panels below.

**Common to all templates:**
- **Fonts:** the real packs use Myriad Pro. Use an open lookalike (Source Sans 3; condensed where narrow). Keep Helvetica-Condensed style for T2.
- **Page sizes** come from the template. Allow a **custom oversized page** for "ACTUAL SIZE" artwork (e.g. a full placement print at 1:1).

**Rulebook seed (Jon may change any of these):**

| Brand | Template |
|---|---|
| Pink London | T2 |
| Ted Baker, Champion, Palm Angels, L/AB | T1 |
| PLAY Palm Angels | T4 |
| Palm Angels components | T3 |
| Off-White | T1 until Jon says otherwise |

## 3. Markup modes (set per template)

- **Numbered mode (T2):** yellow numbered material callouts and red lettered comments, as today.
- **Colour-key mode (T1 Champion / Palm Angels):**
  - The flat is filled in **arbitrary key colours**, one per component.
  - A **variant table** follows. Its header row has, per column, a chip in that key colour plus the component name.
  - One row per colourway / variant, with the variant's colour chip and name in the first column.
  - Cells hold:
    - a Pantone TCX code + name;
    - "#n FROM SWATCH CARD";
    - DTM, CLEAR, BLACK or WHITE;
    - or a reference answer.
  - **The columns are defined per pack** from its components (body fabric, ripstop, hardware, webbing, plastic components, zipper + gauge, bungee cord, buckles, piping, mesh, wet-pouch film, logo screenprint, pop stitching…). They are **not** a fixed list, and there is no EDGE PAINT column unless the product has painted edges.
- **Notes:** free text with **thin leaders** — **cyan** for construction notes ("3MM PADDING ON TOP PORTION"), **red** for dimensions and "PLEASE …" instructions. No circles.
  - Notes are upper case by default; keep mixed case when the designer writes it.
- **The AI read must understand colour-key markup** in uploaded packs and boards (chip → component → value).

## 4. Colourways, variants and multi-style packs

- **A pack can hold several style numbers:** one per colourway (`LAB-HB-#####` ×2, `PLAY-HB-#####` ×2).
  - Uniqueness of style # applies per style, not per pack.
  - The -A/-B suffix model stays for brands that use it (Pink London).
- **Named variants without suffixes** ("DENIM", "LEOPARD") are allowed.
- **Per-colourway attributes:** colour name, fabric (Icon fabric code + swatch #, or supplier card), print file name, lining (Pantone), zipper, label, and **features that apply to one colourway only** (shown as "<STYLE#> ONLY" / "ON THE <VARIANT> VARIANT").
- **SKU block per colourway beside its render:** `SKU# / FILE NAME / COLOR / PANTONE / FABRIC / LINING / ZIPPER`. When a print file is named, Pantone may read "SEE PRINT FILE".
- **Exporting a multi-style pack:**
  - one PDF named for all its style numbers;
  - each style is searchable on the dashboard;
  - the revision applies to the whole pack.

## 5. Units and measurements

- **Unit per brand AND per field.**
  - Champion is in **inches** throughout, including trims and logo widths, written as decimals or fractions with `"` (e.g. `1.5" webbing`).
  - L/AB and PLAY use **cm**.
  - Hardware component sheets and board / padding thicknesses use **mm**.
  - Drop the rule "hardware always in mm". Print a value in the unit it was given, exactly as given.
- **Bug:** the Dimensions section is hidden for Duffels and Rolling duffels (`DIMS_CATEGORIES` in `common.ts`), so `dims.unit` is lost and the unit falls back to cm. Fix it, and add a test.
- **Partial dimensions:** a product may give only some dimensions (drop + W + H; W only for a logo; one value for a component). No forced W × H × D, and no W × H for a logo when only width is known.
- **Size families:** "please sample in the <size> size" means the style exists in several sizes and one is sampled. Store the size family and the sample size.
- **Sets:**
  - a set is pieces of different **types** (cube / pouch), each with its own dimensions (W × H × L, or W × L for flat pieces) and its own material;
  - no overall H × W × D for a set;
  - a nesting order.

## 6. Branding, embellishment and trims

**Many logos per product, per colourway.** Seen: screenprint, sewn patch with zig-zag pop stitching, print on webbing pullers, TPU print, **raised** TPU print, metal plaque **moulded flush**, logo printed on a trolley tube, debossed logo ring with a raised centre, tonal emboss, **knock-out** in a placement print, woven label.

Each logo has:
- method;
- location;
- size (any subset, any unit, or `SCALE_TO_CAD`);
- colour (WHITE / BLACK / Pantone / tonal / finish);
- relief (depth or height in mm);
- artwork file;
- orientation (e.g. a vertical logo reads top-to-bottom);
- colourways it applies to.

**Embellishment methods to add:** trapunto (with motif size), rhinestones (count, motif), TPU print, raised TPU, screenprint, sewn patch, pop stitching (colour), knock-out.

**"ACTUAL SIZE" trim panels:** e.g. a bungee-cord puller with rubber holder, or a doubled webbing puller, drawn 1:1 with their own notes ("DO NOT PRINT CYAN").

**Placement prints on hardside shells:**
- one artwork file placed on the shell at **actual size**;
- knock-out logo;
- gradient colours (no Pantone);
- printed on its own oversized page.

**Lining artwork:**
- "100% ORIGINAL SCALE PRINT / 100% REPEAT";
- motif size instead of tile size;
- ground finish vs print finish (matte ground, shiny heat-seal print).

## 7. Hardware and components (the Palm Angels sheets are the target)

**Bugs to fix:**
- A **Hardware-category pack prints nothing of its own.** The PDF builder never reads `hw.*`.
- A single-dimension part falls back to a **40 mm** drawing height (`html.ts`), so "SIZE 100%" lies.
- The TOP view is never rendered.
- Dimensions print as a list, not on the drawing.

**Component sheet output (T3):**
- one page per part;
- views (FRONT / SIDE / TOP / SECTION) at **true 1:1**;
- every dimension drawn as a dimension line with mm;
- a callout per treatment, phrased as treatment + location ("1.5MM DEBOSSED LOGO ART");
- the finish headline + finish-standard photo;
- an "AI RENDERING" panel;
- a sample photo;
- notes.

Generate one sheet per new or changed part from a style pack, plus a contents list on the style pack linking them.

**The hardware record must hold:**
- views (with drawn dimension sets), any number of dimensions (not W/H/D only), the scale;
- material, including **plastic, rubber, TPU**;
- finish — add **MULTI-COLOR (vacuum-plated iridescent), AGED SILVER, BLACK, Pantone-matched plastic** — plus a finish-standard photo;
- colour for non-metal parts;
- logo artwork file, treatment, relief, orientation;
- mounting / attachment;
- parent part;
- qty and location per style.

**Types to add:** hubcap, wheel, trolley tube / handle system, push button, carry handle, corner guard, strap slider / adjuster, cord lock, bungee-cord puller, webbing puller, zipper slider, eyelet.

**Codes:**
- Formats are per **brand × category**, with literal segments: `PA_LUG_###` for components, while styles are `PA_LUG_#####`; `LAB-HB-#####`, `PLAY-HB-#####`, `PALM_####`, Champion `CH{yy}-###`.
- **Style numbers and component codes are separate sequences.**
- **Bug:** today, with `PA_LUG_###` and style `PA_LUG_10001` in use, the next component code comes out as `PA_LUG_10002`. It must be `PA_LUG_009`. Add a test.

## 8. Packaging, labels and compliance pages (Champion: on by default)

The Champion packs include full pages for these. They stay an optional section (Jon's decision), but **the Rulebook switches them on for Champion**, and each has a page template:

- **Hangtag:**
  - size and fold (front / inside / back panels);
  - paper stock and coating;
  - PMS colours;
  - panel copy;
  - UPC placeholder (FPO);
  - RN#;
  - country of origin;
  - bilingual Prop 65 warning;
  - licensor trademark line.
- **Interior country-of-origin label:** size, content line, RN#, made-in line (EN/FR).
- **Master carton label page:** 2 labels per carton, SKU text ≥ 80 pt, placement, field list.
- **Warranty card, poly bag.**
- Any of these may be a `TO_BE_PROVIDED` placeholder at PROTO.

## 9. Construction and interior vocabulary to add

- padding by location and thickness;
- drop-bottom compartment with board backing (material + mm);
- PVC-backed fabric;
- **PP binding on interior seams of unlined products.** The Interior section is hidden for packing cubes today — fix this;
- elastic compression straps in an X pattern with a centre buckle;
- zipper pocket and zippered compression compartment in **luggage** interiors;
- hardside interior described by **lid half / base half**, not bag walls;
- corner guards with position (e.g. top corners only);
- elastic-top and three-compartment slip pockets;
- dome zip path;
- a label placed **above** a pocket (offset measured either way);
- knot-tie strap with no hardware;
- bandana silhouette;
- for Men's bags: **closure** and **exterior-pocket** questions (they have none today).

## 10. Library

- **Icon fabric codes are cross-brand.** `F-####` + swatch # (e.g. "F-#### swatch #n") is used by more than one brand. Materials can be shared across brands and are searchable by F-code.
- **Hand-numbered supplier cards** (shade written by hand, no chip box): select the shade by number.
- **"Quality reference" cards:** linked as quality only, with no colour chosen.
- **Card fields to add:** thread count (e.g. 210T — not denier), peel strength, rub fastness, width, thickness.
- **Privacy:** supplier cards can show bank-account and phone numbers. The card reader must **never** store or print bank details, phone numbers or addresses. Redact them from stored card images used on pages, or crop to the chip.

## 11. AI read and validation

**AI read:**
- **Reference photos of other brands' products are normal** (used for shape and construction). Treat them as references only.
  - Never take a spec off a reference product as this style's spec.
  - If dimensions visibly come from a reference product, flag "taken from reference product — confirm".
  - The pack prints the reference with its caption; it does not describe the reference brand.
- **Read board text:** SKU blocks, colour-key chips + variant tables, "PLEASE …" instructions, "<SKU> ONLY" notes, "ACTUAL SIZE" panels, red-frame reference captions.
- **Per-colourway reading:** one style # per render, and features present on one colourway only.

**Validator — errors found in the real packs that the app must catch** (warnings at PROTO):
- a dimension printed differently from the dimension line it labels;
- "SEE NEXT PAGE(S)" when no such page exists;
- the same colour named differently across pages;
- a swatch-chip id in the table that doesn't match the card;
- a set piece missing a dimension label;
- hidden or leftover text layers;
- a finish that conflicts between the render and the component sheet;
- a material description that conflicts with its card (e.g. "smooth" vs a pebble-grain card);
- interior and exterior accent colours that differ (info only).

**Spell-check / glossary:**
- **Typos to correct:** SCREEPRINT→SCREENPRINT, RIPTSTOP→RIPSTOP, MENS→MEN'S, "MULTI- COLOR"→MULTI-COLOR.
- **Trade terms to accept:** RIPSTOP, WETPOUCH (wet pouch), MULTI, MULTI-COLOR, SWIFTACH, FPO, RN#, COO, UPC, TCX, PMS, TPU, PE, PP, ABS, PC, ORG, CRM, SKU#, F-####, TRAPUNTO, BEVELED, KNOCK-OUT.
- **Glossary fix:** DEPTH maps to 厚度, but swatch cards use 厚度 for material thickness. Use **深度** for bag depth.
